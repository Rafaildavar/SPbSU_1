# Описание алгоритма подсчета уникальных IPv6-адресов

## Алгоритм решения

Для решения задачи подсчета уникальных IPv6-адресов в файле, который может содержать до 10⁹ строк и не помещается в оперативную память, используется алгоритм **внешней сортировки (external sort)** с последующим подсчетом уникальных элементов.

### Основные этапы:

#### 1. Нормализация IPv6-адресов

Каждый IPv6-адрес приводится к канонической форме: 8 групп по 4 шестнадцатеричные цифры в нижнем регистре, разделенные двоеточиями.

**Алгоритм нормализации:**
- Обработка сжатия нулей (`::`) — восстановление пропущенных групп нулей
- Дополнение каждой группы до 4 hex цифр ведущими нулями
- Приведение всех букв к нижнему регистру
- Гарантированное получение ровно 8 групп

**Примеры:**
- `2001:0DB0:0000:123A:0000:0000:0000:0030` → `2001:0db0:0000:123a:0000:0000:0000:0030`
- `2001:db0:0:123a::30` → `2001:0db0:0000:123a:0000:0000:0000:0030`
- `CD10:9A90:F9BB:E5B6:F714:86E7:F1BB:BDFC` → `cd10:9a90:f9bb:e5b6:f714:86e7:f1bb:bdfc`

#### 2. Разбиение файла на чанки

Файл разбивается на части (чанки) размером ~100 МБ, которые помещаются в оперативную память. Это позволяет обрабатывать файлы любого размера при ограниченной памяти (порядка 1 ГБ).

#### 3. Обработка каждого чанка

Для каждого чанка выполняется:
- Нормализация всех IPv6-адресов в чанке
- Сортировка нормализованных адресов
- Удаление дубликатов внутри чанка (оптимизация)
- Сохранение результата во временный отсортированный файл

**Временная сложность:** O(n log n) для каждого чанка, где n — количество строк в чанке

#### 4. K-way merge и подсчет уникальных адресов

Отсортированные чанки объединяются с использованием алгоритма **k-way merge**:
- Используется структура данных "куча" (heap) для эффективного слияния
- На каждом шаге выбирается минимальный элемент среди всех чанков
- Подсчет уникальных адресов выполняется за один проход: если текущий адрес отличается от предыдущего, увеличивается счетчик

**Временная сложность:** O(N log k), где N — общее количество строк, k — количество чанков  
**Пространственная сложность:** O(k) — в памяти хранится по одной строке из каждого чанка

### Преимущества алгоритма:

1. **Эффективность по памяти:** Используется только O(k) дополнительной памяти, где k — количество чанков (обычно десятки или сотни)
2. **Масштабируемость:** Работает с файлами любого размера, ограниченными только дисковым пространством
3. **Корректность:** Гарантирует точный подсчет уникальных адресов без потери данных
4. **Оптимизация:** Удаление дубликатов внутри чанков уменьшает объем данных для merge

### Общая оценка сложности:

- **Временная сложность:** O(N log N), где N — количество строк в файле
- **Пространственная сложность:** O(CHUNK_SIZE) для обработки чанков + O(k) для merge, где k << N

### Пример работы:

**Входной файл:**
```
2001:0DB0:0000:123A:0000:0000:0000:0030
2001:db0:0:123a::30
CD10:9A90:F9BB:E5B6:F714:86E7:F1BB:BDFC
DF96:A23D:8BA9:BAA0:A807:FB50:F9CD:B266
9D64:9DB4:B0FE:B3C2:F09F:8DE1:EC59:987D
```

**Результат:** 4 уникальных адреса

Первые два адреса после нормализации становятся одинаковыми (`2001:0db0:0000:123a:0000:0000:0000:0030`), поэтому уникальных адресов 4.
