# Подсчет количества уникальных IPv6-адресов в большом файле

## Описание задачи

Реализована программа для подсчета количества уникальных IPv6-адресов в текстовом файле, который может содержать до 10⁹ строк. Программа работает при ограниченном объеме оперативной памяти (порядка 1 ГБ) и использует алгоритм внешней сортировки.

## Описание алгоритма

### Общая идея

Для обработки файлов, которые не помещаются в оперативную память, используется алгоритм **внешней сортировки (external sort)** с последующим подсчетом уникальных элементов за один проход.

### Этапы работы алгоритма

#### 1. Нормализация IPv6 адресов

Каждый IPv6 адрес приводится к канонической форме:
- **Формат**: 8 групп по 4 шестнадцатеричные цифры в нижнем регистре, разделенные двоеточиями
- **Пример**: `2001:0db0:0000:123a:0000:0000:0000:0030`

Алгоритм нормализации:
- Обработка сжатия нулей (`::`) - восстановление пропущенных групп нулей
- Дополнение каждой группы до 4 hex цифр ведущими нулями
- Приведение всех букв к нижнему регистру
- Гарантированное получение ровно 8 групп

#### 2. Разбиение файла на чанки

Файл разбивается на части (чанки), которые помещаются в оперативную память:
- Размер чанка: ~100 МБ (настраивается через константу `CHUNK_SIZE`)
- Чанки читаются построчно до достижения лимита размера
- Это позволяет обрабатывать файлы любого размера при ограниченной памяти

#### 3. Обработка каждого чанка

Для каждого чанка выполняется:
- Нормализация всех IPv6 адресов в чанке
- Сортировка нормализованных адресов
- Удаление дубликатов внутри чанка (оптимизация)
- Сохранение результата во временный отсортированный файл

**Временная сложность**: O(n log n) для каждого чанка, где n - количество строк в чанке

#### 4. K-way merge и подсчет уникальных адресов

Отсортированные чанки объединяются с использованием алгоритма **k-way merge**:
- Используется структура данных "куча" (heap) для эффективного слияния
- На каждом шаге выбирается минимальный элемент среди всех чанков
- Подсчет уникальных адресов выполняется за один проход: если текущий адрес отличается от предыдущего, увеличивается счетчик

**Временная сложность**: O(N log k), где N - общее количество строк, k - количество чанков
**Пространственная сложность**: O(k) - в памяти хранится по одной строке из каждого чанка

### Преимущества алгоритма

1. **Эффективность по памяти**: Используется только O(k) дополнительной памяти, где k - количество чанков (обычно десятки или сотни)
2. **Масштабируемость**: Работает с файлами любого размера, ограниченными только дисковым пространством
3. **Корректность**: Гарантирует точный подсчет уникальных адресов без потери данных
4. **Оптимизация**: Удаление дубликатов внутри чанков уменьшает объем данных для merge

### Оценка сложности

- **Временная сложность**: O(N log N), где N - количество строк в файле
- **Пространственная сложность**: O(CHUNK_SIZE) для обработки чанков + O(k) для merge, где k << N

## Использование

### Основная программа

```bash
python3 count_unique_ipv6.py <input_file> <output_file>
```

**Пример:**
```bash
python3 count_unique_ipv6.py input.txt output.txt
```

### Генератор тестовых данных

**Генератор из задания (task-1/generate_data.py):**
```bash
# Генерация файла с заданным количеством уникальных адресов и общим количеством строк
python3 task-1/generate_data.py output_file.txt num_unique total_size [--seed SEED]

# Пример: 10 уникальных адресов, 50 строк всего
python3 task-1/generate_data.py test_input.txt 10 50 --seed 42
```

**Вспомогательный генератор (generate_test_data.py):**
```bash
# Генерация примера из условия задачи
python3 generate_test_data.py example

# Генерация файла с заданным количеством строк
python3 generate_test_data.py test_input.txt 1000000
```

### Тестирование нормализации

```bash
python3 ipv6_normalizer.py
```

### Тестирование с генератором из задания

```bash
# Генерируем тестовый файл: 10 уникальных адресов, 50 строк всего
python3 task-1/generate_data.py test_input.txt 10 50 --seed 42

# Запускаем программу подсчета
python3 count_unique_ipv6.py test_input.txt test_output.txt

# Проверяем результат (должно быть 10)
cat test_output.txt
```

## Пример работы

**Входной файл (input.txt):**
```
2001:0DB0:0000:123A:0000:0000:0000:0030
2001:db0:0:123a::30
CD10:9A90:F9BB:E5B6:F714:86E7:F1BB:BDFC
DF96:A23D:8BA9:BAA0:A807:FB50:F9CD:B266
9D64:9DB4:B0FE:B3C2:F09F:8DE1:EC59:987D
```

**Выходной файл (output.txt):**
```
4
```

**Пояснение:** Первые два адреса (`2001:0DB0:0000:123A:0000:0000:0000:0030` и `2001:db0:0:123a::30`) после нормализации становятся одинаковыми (`2001:0db0:0000:123a:0000:0000:0000:0030`), поэтому уникальных адресов 4.

## Требования

- Python 3.6 или выше
- Только стандартная библиотека Python (без внешних зависимостей)

## Особенности реализации

1. **Обработка ошибок**: Программа корректно обрабатывает ошибки нормализации и продолжает работу
2. **Временные файлы**: Автоматически создаются и удаляются после завершения работы
3. **Прогресс**: Выводит информацию о прогрессе обработки в stderr
4. **Кодировка**: Поддержка UTF-8 для корректной обработки всех символов

## Возможные оптимизации

1. **Многопоточность**: Параллельная обработка чанков для ускорения работы на многоядерных системах
2. **Хеширование**: Использование хеш-таблиц для более быстрого сравнения адресов (но требует больше памяти)
3. **Сжатие**: Использование сжатия временных файлов для экономии дискового пространства
4. **Блочное чтение**: Оптимизация I/O операций для больших файлов
